## 1. Stack decisions

### Decision: TypeScript 5.x / Next.js 15 App Router
- **Rationale**: Existing AIT routes (`src/app/api/ait/`) use this stack. Constitution Principle III requires matching the first module's structure for slices 2+.
- **Alternatives considered**: Express + separate React SPA — rejected (adds a second server process, conflicts with existing monorepo layout).

### Decision: Drizzle ORM (dual adapter — `pg` + `better-sqlite3`)
- **Rationale**: `data/schema.sql` already defines all tables. Drizzle can introspect them (`drizzle-kit pull`) without rewriting schema. The SQLite adapter enables zero-config local testing with no running Postgres.
- **Alternatives considered**: Prisma — heavier codegen and harder to run against an existing schema without a full migration history. Raw `pg` — no type safety, more boilerplate.

### Decision: Zod for input validation
- **Rationale**: Already used in `src/app/api/ait/` routes (inferred from project stack). Zod validators are the authoritative runtime enforcement of spec §5.1 constraints (enum values, max lengths, numeric bounds).
- **Alternatives considered**: `class-validator` — heavier, decorator-based; worse tree-shaking.

### Decision: Cloudinary for image storage
- **Rationale**: Explicitly listed as a PRF dependency in spec §1. Handles JPG/JPEG/PNG/WEBP upload, size enforcement (10MB), and auto-resize (min 1280×720 per BR-008).
- **Testing approach**: `msw` handler returns a fake Cloudinary response. No actual upload in CI.

### Decision: OpenAI API for AI refinement (FR-007)
- **Rationale**: Explicitly listed as a PRF dependency. FR-007 / BR-011–013 define the contract: factual rewrite, original preserved, draft never auto-saved.
- **Testing approach**: `msw` stubs the OpenAI completion endpoint. Tests verify the service never auto-accepts the draft.
- **Graceful degradation**: If `OPENAI_API_KEY` is absent, the route returns `503 AI service unavailable` — spec §3 edge case "AI refinement service is unavailable".

## 3. Business-rule implementation notes

| BR | Implementation approach |
|----|------------------------|
| BR-001 | Middleware checks `agency_profiles.user_id = session.userId` before PATCH |
| BR-002 | Service checks `provider_profiles.user_id = session.userId` or `experiences.provider_id = session.providerId` before write |
| BR-003 | Route-level guard: HDT/UBND role → reject PATCH/POST on profile content |
| BR-004 | `visibility.ts` exports `filterAgencyFields(actor, profile)` and `filterProviderFields(actor, profile)` — called by GET routes |
| BR-005 | `provider-service.ts:reviewProvider()` checks `ubnd_village_assignments.village_id = provider_profiles.village_id` |
| BR-006 | `provider-service.ts:updateProvider()` checks required fields; if all present → `version_status = Pending Verification`; else `Draft` |
| BR-007 | GET routes return published version fields when `published_version_no IS NOT NULL` and a new revision is pending |
| BR-008 | Zod schema validates MIME type and file size; Cloudinary enforces min resolution on upload |
| BR-009 | Experience create/update validates that `profile_media` contains ≥1 row for each of `Activity`, `Space`, `Product` categories |
| BR-010 | Zod: `price_per_person > 0`, `max_participants > 0`, `notice_period_hours >= 0` |
| BR-011–013 | `ai-service.ts` returns draft only; no auto-save path exists in the API; acceptance is a separate PATCH call on the owning profile/experience route |
| BR-014 | `experience-service.ts:updateExperience()` checks for active bookings before allowing mutation of locked fields |
| BR-015 | `experience-service.ts:deleteImage()` counts remaining images per category; rejects if count would reach 0 |
| BR-016 | Frontend-only (lightbox behavior on EXP068) — no API change |
| BR-017 | `agency-service.ts:updateAgency()` detects `company_name` or `tax_id` change → inserts `agency_major_change_requests` row instead of direct update |
| BR-018 | `provider-service.ts:updateProvider()` detects major field change on a Verified provider → new version row with `Pending Verification`; keeps `published_version_no` unchanged |
| BR-019 | `experience-service.ts:deleteExperience()` checks `bookings` status; blocks on active, archives on historical, hard-deletes on none |
| BR-020 | Experience PATCH does not trigger provider re-verification check |
| BR-021 | Operating hours PATCH writes to `provider_operating_hours` rows; no Experience-level hours created |
